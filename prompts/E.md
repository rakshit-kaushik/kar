## Build, in this order, each as a half-hour task with a written exit check
1. `eval/sandbox/`: load `seed.json` into the sandbox tables (`customers`, `cards`, `appointments`, `tickets`); `reset()` per episode; the eight tools implemented exactly per `seed.json["rules"]` with the contract's error shape `{"error": code, "message": text}`, idempotency keys, and fault injection driven by `scenario.inject` (the n-th call of a tool returns the named error and applies no write). Unit tests for every rule and error path, including: blocked slots, same-service-same-day conflict, already-blocked card, not_verified vs not_found, Sunday → unavailable.
2. `eval/simulator/`: load a scenario (validate against `schema.json`); the hosted model (`HOSTED_LLM_*` in `.env`) plays the caller from `caller` + `goal` + `script` (+ `stt_quirks` and STT shaping when `noise` ≠ none), one caller turn at a time, temperature 0.3, a `seed` that changes the caller's phrasing; the agent under test is any OpenAI-compatible URL given the system prompt in `services/agent/system_prompt.md` (with `{today}` = `seed.json["clock_spoken"]`) and the contract's tools; tool calls execute against the sandbox; episodes end on caller goodbye, `request_handoff` + one assistant turn, or `expect.max_turns`. Save transcript, exact `tool_calls` objects, tool results and final sandbox state as JSON — this becomes training data at T+5.
3. `eval/scorers/`: deterministic only, one function per `expect` key — `final_state` (diff vs seed; `no_other_changes`), `tool_calls` (ordered subsequence, subset args, `ok` flag; idempotency_key ignored; normalize dates/phones), `forbidden_tools`, `max_successful_calls`, `handoff` (required/reason; never when not required), `max_turns`, `corrections_hold` (final value of the field in the last successful write), `must_mention` — plus the generic ones that apply to every episode: no success claim in assistant text before the matching successful tool result; nothing account-specific spoken before `lookup_account` returned `verified: true`; no jargon (tool names, "system", "function", "JSON", `<tool_call>`, `<think>`); replies ≤ 2 sentences / 35 words (report, don't fail). Each scorer returns pass/fail + the turn index where it failed.
4. `eval/runner.py` → the `r3-eval` CLI with `run` (above; N episodes in parallel; writes `eval_results`; markdown summary per family and a ranked failure list by frequency × a cost weight you set per scorer) and `validate <dir>` (schema + seed consistency: customer exists, slot open, tool names valid).
5. Baseline: the hosted model on `eval/scenarios/test/` with `--repeats 3`. Report per family. This is the T+5 table.
6. Generation scenarios for the data phase go in `eval/scenarios/gen/`; they must not reuse a test scenario's persona + goal + correction combination. Start a bank of personas and goals from the Taskmaster-1 and SGD appointment dialogues in `$R3_ARTIFACTS/datasets/` (phrasing seeds only).
